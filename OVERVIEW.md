# Обзор кода проекта

Документ предназначен для краткого, но достаточного представления всех исходников перед преподавателем. За счёт подробных описаний можно быстро ответить на вопросы по архитектуре и назначению файлов.

## Корневая структура
- `python_defrag/` — основной код.
- `tests/` — тесты и служебные сценарии.
- `images/` — тестовые образы FAT32.
- `OVERVIEW.md` — текущий документ.

## Модуль `python_defrag`

### `python_defrag/parser/fat32_parser.py`
Низкоуровневый драйвер работы с образом FAT32. Реализует:
- безопасное открытие файла и контекстный менеджер;
- чтение/запись кластеров, вычисление смещений по кластерам и таблице FAT;
- операции с FAT-записями (чтение цепочки, запись нового значения, синхронизация);
- валидацию boot-сектора и извлечение ключевых параметров (размеры, корневой кластер, количество FAT и т.д.).
Именно этот слой обеспечивает прямой доступ к данным образа и является фундаментом для анализа и дефрагментации.

### `python_defrag/parser/directory_entry.py`
Отвечает за разбор 32-байтовых записей каталогов. Содержит:
- dataclass `DirectoryEntry` с удобными полями (имя, атрибуты, кластеры, размеры, даты);
- класс `DirectoryParser`, который проходит по «сырому» блоку каталога, фильтрует удалённые/LFN/служебные записи, корректно декодирует имена и времена.
Используется анализатором при обходе файловой системы.

### `python_defrag/analysis/analyser.py`
Класс `FAT32Analyzer` строит полную картину тома:
- рекурсивно обходит каталоги (опираясь на `DirectoryParser` и парсер кластеров);
- собирает цепочки кластеров для каждого файла/директории и превращает их в экстенты;
- строит bitmap занятых кластеров, определяет свободные участки, считает метрики фрагментации;
- формирует читаемый отчёт (статистика, списки файлов/директорий, свободные экстенты);
- предоставляет вспомогательные функции вроде `print_summary`, чтобы быстро вывести итоги в консоль.
Файл также содержит вспомогательные структуры данных (`FileRecord`) и утилиты для преобразования цепочек в экстенты.

### `python_defrag/engine/defrag_engine.py`
Дефрагментационный движок, выполняющий основные шаги:
1. Планирование (`plan_defragmentation`): выбирает фрагментированные файлы, ищет подходящие свободные диапазоны, формирует список переносов (каждый с описанием источника и цели).
2. Создание копии исходного образа (`create_output_image`), чтобы не менять оригинал.
3. Перемещение данных (`move_file_clusters`): читает кластеры исходного файла, записывает в новый диапазон, обновляет FAT-цепочки и записи каталогов (с рекурсивным обходом подкаталогов).
4. Подведение итогов (`execute_defragmentation`, `defragment`): собирает статистику успешных/неуспешных переносов, возвращает отчёт.
Движок активно логирует ошибки, тщательно обновляет записи каталогов (поиск производится по всему дереву), а также ведёт список изменённых кластеров, чтобы корректно очищать старые цепочки.

### `python_defrag/engine/cli.py`
Консольный интерфейс. Позволяет:
- запускать анализ без выполнения переноса;
- вывести план операций;
- выполнить дефрагментацию сразу в новый файл;
- указать путь к образу и файлу для сохранения результата.
CLI использует `argparse`, а вся логика делегируется классу `DefragmentationEngine`.

## Тесты и утилиты (`tests/`)

### `tests/test_engine.py`
Юнит-тесты движка. Покрывают инициализацию, получение отчёта анализа и корректность планирования. Проверяется структура каждой операции (тип данных, наличие обязательных ключей, адекватность значений).

### `tests/test_integration.py`
Интеграционные тесты связки `FAT32Parser + FAT32Analyzer`. Проверяют, что отчёт содержит все ключевые части, а обход каталогов действительно возвращает хотя бы корень.

### `tests/test_all.py`
Скрипт для «smoke»-прогонов. По флагам можно отключить части теста (парсер, анализатор, движок) и быстро показать преподавателю полную цепочку работы проекта, включая вывод статистики.

### `tests/test_parser_cli.py`
Мини-клиент, который выводит сведения boot-сектора и содержимое корневого каталога. Удобен для ручной демонстрации и проверки парсера.

### `tests/test_analyser_cli.py`
CLI для анализа: строит отчёт и показывает топ самых фрагментированных файлов.

### `tests/test_fragmented.py`
Заготовка под дополнительные сценарии (можно использовать для расширения покрытия).

## Дополнительно
- `images/` содержит образы FAT32 (фрагментированные и дефрагментированные) для демонстрации и тестов.
- `README.md` можно использовать как точку входа, но подробности именно здесь, в `OVERVIEW.md`.

Такой обзор позволяет уверенно рассказать о каждой части проекта, показать зависимость уровней (парсер → анализатор → движок → CLI) и аргументировать качество тестового покрытия.
